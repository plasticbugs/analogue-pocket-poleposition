# The Z8002 core

Pole Position runs its game and road logic on two Zilog Z8002s at 3.072 MHz.
No open-source Z8000 HDL core exists, so this one was written for this project.

It is deliberately **not** a model of the chip's bus protocol. It is an
executable copy of MAME 0.288's `z8000` core: the same operand decoding, the
same flag rules — including the ones that are arguably bugs — the same cycle
costs, the same interrupt latching. MAME is the oracle the rest of this core is
checked against, so the CPU is held to MAME rather than to the Zilog manual.
Where the two disagree (§5), MAME wins.

## 2. Design

**Decode.** MAME dispatches on the first opcode word through a table of
(first, last, step) ranges, later entries overriding earlier ones.
`gen_decode.py` replays that table and emits a decode function returning a
35-bit control word: `{cycles, class, size, alu op, addressing mode, variant,
extension words, privileged, EPU}`. Each of MAME's 519 table entries is
classified by handler name; an unrecognised name is a hard error, so a table
change cannot slip through the generator unnoticed.

**Execution.** A fetch/decode front end, then one micro-sequence per handler
class (ALU, unary, exchange, stack, block move, LDM, I/O, …). Each micro-step
changes at most one architectural register, and the steps follow the order of
the C++ statements they mirror. That is what makes register aliasing come out
right without special cases: `push @r15,@r15`, `ldm` overwriting its own base
register, `call @r15` taking its target after the push, `trib` whose count
register may be the one holding its result, and so on.

One ALU, one barrel shifter and one register write port serve the whole core;
the branches choose operands and the shared epilogue applies the result.
(Before that refactor the same design cost 7,596 ALUTs instead of 5,826.)

**Timing.** Not bus cycles — MAME's cycle budget (`docs/interfaces.md`): `cen`
adds one credit per CPU clock, an instruction starts only with credit > 0 and
is charged its table cost at decode, including MAME's data-dependent
adjustments (MULTW by zero refunds 52 cycles; MULTL charges 7 per set bit of
the multiplicand, or refunds 252 for a zero operand). Multiply is one DSP
multiply; divide is a restoring divider, 32 or 64 iterations.

Measured against the budget on the game's own code: **6.0 clocks per
instruction used, against 98.9 available** (6.18 CPU cycles × 16). The worst
single step seen anywhere is 103 clocks (`divl rqd,addr(rs)`), against 11,936
for that instruction. The core cannot fall behind the budget.

**Bus.** One request/acknowledge port for memory and I/O, byte or word, with
the word address rounded down as MAME's memory system does. `bus_ack` may come
in the same cycle as the request or any number of cycles later; the harness
randomises the latency from 0 to 2 cycles on every access.

**Reset.** `reset` follows MAME's `device_reset`: it requests the reset
sequence (FCW from `0x0002`, PC from `0x0004`) and clears the halt flag, but
does not clear the registers — a soft reset in MAME does not either. Power-up
values come from the register initialisers, which match MAME's
`clear_internal_state`. Unlike MAME, which suspends the CPU at a scheduling
boundary, the RTL abandons any instruction in progress; the two cannot be
compared cycle for cycle here, since MAME's own reset timing is a scheduler
artefact.

## 3. Interrupt inputs

`nmi` is edge triggered. `nvi`/`vi` are levels, plus `nvi_evt`/`vi_evt`
one-cycle pulses. **The pulses are the one addition to the interface in
`docs/interfaces.md`.** They are needed to be faithful: MAME acts on every
`set_input_line` call, not only on changes, and Pole Position makes redundant
calls in both directions — the scanline callback asserts NVI every frame
whether or not it is already asserted, and `z8002_nvi_enable_w` clears it on
every write of 0 to the enable latch. Both have visible effects:

* an ASSERT while the line is already high re-arms a request that has already
  been serviced;
* a CLEAR while the line is already low drops a latched request, if the
  matching enable bit is off at that moment.

So `*_evt` means "a `set_input_line` call happened this cycle"; the level says
whether it asserts or clears. Glue that only ever changes levels can tie them
low and rely on edge detection. Both were found by the harness, not by
reading: the random campaign fails within a few thousand steps without them.

### What the Pole Position glue has to drive

Each Z8002 has its own NVI line and its own enable latch, exactly as in
`polepos.cpp`:

```systemverilog
// scanline 240, once per frame, to both CPUs
if (line == 240 && nvi_mask[i]) begin nvi[i] <= 1'b1; nvi_evt[i] <= 1'b1; end
// the CPU's own write to 0x6000 (mirrored through 0x1ffe), one latch per CPU
if (wr_6000) begin
    nvi_mask[i] <= wdata[0];
    if (!wdata[0]) begin nvi[i] <= 1'b0; nvi_evt[i] <= 1'b1; end
end
// nvi_evt is a single cycle
nvi_evt[i] <= 1'b0;   // default, overridden above
```

and `reset` comes from the LS259 at `0xA000` (bit 4 resets sub 1, bit 5 sub 2,
active low), so `reset = ~latch[4]`. `vi`, `vi_evt` and `nmi` are tied low:
nothing on the board drives them.

The latch itself follows `execute_set_input` and `CHANGE_FCW`: an assert
latches only while the matching enable bit is set, a clear only takes effect
while it is clear, and enabling NVIE/VIE with the line asserted latches a
request there and then. Line events are evaluated before the sequencer's
boundary check in the same cycle, because MAME applies them between
instructions.

## 4. Verification

`./sim/z8002/build.sh` regenerates the decode table, rebuilds the C++
reference from MAME's own `z8000ops.hxx`/`z8000tbl.hxx`, and builds the
harness. Both sides keep their own 64K memory. After every step — one
iteration of MAME's `execute_run()` loop body, so an interrupt entry and/or one
instruction — the harness compares:

* all 16 registers, PC, FCW, NSPOFF/NSPSEG, PSAPOFF/PSAPSEG, REFRESH, the
  interrupt request latch, the halt flag;
* the cycle cost charged (the RTL's credit against a model of MAME's `icount`);
* the exact sequence of bus writes (address, size, value, I/O or memory);
* the set of bus reads, and the whole 64K of memory.

### Campaigns

`./sim/z8002/regress.sh` runs the standard set in about a minute. Results:

| campaign | coverage | result |
|---|---|---|
| `dab` | all 2048 DAB inputs (value × C × H × D) | match |
| `directed <seed> <reps>` | every one of the 65536 first words, each from a random machine state, system and user mode | match — 1,310,720 instructions per seed at 20 reps (seeds 1, 2, 3, 12), 5,242,880 in total |
| `random <n> <seed> --irq` | random code and data, random NMI/NVI/VI line events and re-assertions at instruction boundaries | match — 200,000 steps × seeds 8–19, and 1,000,000 × seeds 101–104 |
| `rom build/z8002/sub1.bin <n>` | the real sub-CPU 1 ROM from reset, NVI once per frame, acknowledged through the `0x6000` latch | match — 3,000,000 instructions |
| `rom build/z8002/sub2.bin <n>` | sub-CPU 2, same | match — 3,000,000 instructions |

Randomised runs skip the handful of instructions whose MAME behaviour is C++
undefined behaviour — shifts by 32 or more, where MAME shifts an `int` by the
count without masking. They are detected both before the step and after it
(an interrupt can land on one the pre-check never saw), and both sides are
then resynchronised. Those are the only instructions excluded, the exclusion
lives in the harness rather than the core, and runs report how many were
skipped (21 in 100,000 steps of random code).

**The harness was checked against a known fault.** Deleting one line from the
ALU — `ADDB` clearing the DA flag — makes the directed campaign fail at opcode
`0004` on its fifth step and the random campaign at step 2651. Restoring it
makes both pass again. A signedness bug found this way is worth recording: a
conditional expression mixing `$signed(x) >>> n` with an unsigned alternative
makes the whole expression unsigned, so the arithmetic shift zero-filled;
written as two statements it is correct, and the campaign that found it is
`directed`, at `sdab`.

### Against the real machine

The reference is MAME's code, but compiled outside MAME. To show the
surroundings are right too, `:sub1` was traced inside MAME itself (`trace
sub1.tr,:sub1,noloop` via the Lua debugger interface) from power-on, and the
same ROM was run in the harness from reset:

**584,431 instructions in a row, from reset, follow the real machine's PC
sequence exactly.** The two then part company at

```
34C0: test    %8090
34C4: jr      eq/z,%34c0
```

— a spin on shared RAM `0x8090`, which on the real board is written by the
Z80. The bench has no Z80, so it spins where MAME moves on. That is the
expected boundary; everything before it is Z80-independent.

## 5. MAME quirks reproduced deliberately

Places where MAME departs from the Zilog documentation. The core copies MAME,
because the rest of this project is verified against MAME.

| opcode | MAME does | documented behaviour |
|---|---|---|
| `0C d0 00` `comb @rd` | takes the address register from NIB3, which the table forces to 0 — so always R0 | address register is NIB2 |
| `4C 00 00` `comb addr` | reads a **word** and complements its low byte | reads a byte |
| `18 s0 dd` `multl rqd,@rs` | multiplies by the **register** RL(s) | multiplies by memory at `@rs` |
| `BA s0 2r` `cpsib` | repeats like `cpsirb` (its word twin `cpsi` does not) | does not repeat |
| `15 s0 d0` `popl rd,@rs` | pops into the register RL(d) | writes memory at `@rd` |
| `B2 d3 …` `sdlb rbd,rs` | shifts right by the **unsigned** low byte of rs | signed dynamic shift |
| `B0 d0 00` `dab` | uses a lookup table where any of H or C on an add gives a flat +0x66, and every subtract case with H or C set carries out | standard BCD adjust |

Interrupt acknowledge pushes `0xFFFF` as the vector word, which is what MAME's
unbound `m_iack_in` returns.

Segmented mode, the Z8001 stack-pointer pair and the segment trap are not
implemented: the Z8002 has no segmented mode, `CHANGE_FCW` masks the bit off,
and nothing in this machine can raise a segment trap.

## 6. Synthesis

**Integration change.** In the whole-core compile the slowest path on the
49.152 MHz clock was inside this core: `op0` through the generated decode table
into the credit adder in `S_DECODE`, at -1.04 ns. The decode word is now
registered in a new state, `S_PREDEC`, between `S_FETCH0` and `S_DECODE`. The
cost is still charged in `S_DECODE`, so the credit arithmetic is unchanged; the
extra clock per instruction comes out of a budget the core uses 6 of ~99 clocks
of. `sim/z8002/regress.sh` passes unchanged afterwards (dab, directed ×2,
random ×6 with interrupts, both ROMs).

(A first attempt deferred the credit charge by one clock instead. The harness
caught it: the 32767 credit ceiling then saw the uncharged value and dropped a
tick, and the ROM runs rely on 16-bit credit wrap. Reverted.)

Two more paths followed as the fitter moved on, both fixed the same way —
computing from registers that cannot change before they are used:

* MULTL's cost (7 per set bit of the multiplicand): register mux, popcount and
  x7 in front of the credit adder. `mul_pop7` is now computed every clock.
* Shift counts: count register select and negation in front of the barrel
  shifter. Every shift form fetches its count word in `S_EXT1` and executes in
  `S_EXEC` the next clock, so the counts are taken from the word as it arrives.

After all three, in the whole core: worst setup slack +0.948 ns (slow 85C),
+1.340 ns (slow 0C), worst hold +0.125 ns. `sim/z8002/regress.sh full` and two
1M-instruction random campaigns with interrupts match MAME on the final RTL.

### Standalone numbers (before the change above)

Quartus 18.1, 5CEBA4F23C8 (the Pocket's device), one instance in a wrapper
that drives every input from an LFSR and XOR-reduces every output, so nothing
optimises away and every port sits on a real register-to-register path:
`build/z8002/quartus/`, rebuilt with

```sh
docker run --rm --platform linux/amd64 -v "$PWD":/build \
    -w /build/build/z8002/quartus raetro/quartus:pocket \
    sh -c "quartus_map --read_settings_files=on z8002_synth.qpf -c z8002_synth && \
           quartus_fit --read_settings_files=on z8002_synth.qpf -c z8002_synth && \
           quartus_sta z8002_synth.qpf -c z8002_synth"
```

| one instance, standard fit, HIGH PERFORMANCE EFFORT | |
|---|---|
| ALMs (fitter) | 4,149 of 18,480 (22%) |
| Registers | 949 |
| DSP blocks | 3 |
| Combinational ALUTs after synthesis | 5,826 |
| Fmax, slow 1100mV 85C | 50.64 MHz |
| Fmax, slow 1100mV 0C | 49.38 MHz |
| Setup slack at 49.152 MHz (20.345 ns) | +0.598 ns (85C), +0.092 ns (0C) |
| Hold slack | +0.477 ns (slow), +0.166 ns (fast) |

It closes at 49.152 MHz on its own, but the 0C corner has less than 0.1 ns to
spare, so the whole-core compile — with routing pressure from everything else
— must be checked, and the path to shorten if it fails is a register read
through the ALU into the write mux. The same design that costs 5,826 ALUTs
cost 7,596 before the shared-ALU refactor; if the two instances (about 8,300
ALMs) are too much for the finished core, the next thing to attack is the
decode function, a 16-bit to 35-bit lookup written as if-chains — folding the
cycle count into a second small table indexed by the opcode's high byte would
take a large bite out of it.

The fit was run with `--cpus 2 --memory 3g` because several other Quartus
containers were compiling at the same time; the settings that produced these
numbers are in `build/z8002/quartus/z8002_synth.qsf`.
